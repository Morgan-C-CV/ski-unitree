# G1 滑雪分层强化学习训练方案 V1

版本：0.1（实施设计草案）  
日期：2026-09-08  
项目：MuJoCo / Unitree G1 滑雪 showcase  
建议项目路径：`docs/ski-rl-training-strategy-v1.md`  
配套文档：`docs/ski-physics-environment-v1.md`

> 本文整合课程学习、HLC/LLC、观测与动作接口、奖励、多教师蒸馏及评测方案。所有网络尺寸、控制频率、采样比例和验收阈值均为开发建议，尚未经本项目训练验证。本文不是可直接运行的实现，也不保证竞技动作最终可达。

## 1. 目标与首版边界

最终目标是一个 HLC 加一个统一、带任务条件的 LLC，完成选线、调速、地形适应、指定跳跃动作和落地恢复。统一 LLC 可以拥有技能输入，不要求取消任务条件，也不要求将 HLC 与 LLC 压成单个网络。

首个可验收版本只解决：固定均质斜面上，LLC 接收目标运动方向和速度，完成直滑、连续左右转弯、减速和稳定滑出；随后由 HLC 驱动通过连续旗门。

猫跳和跳跃作为后续能力扩展。站立、直滑、转弯不各训练一套永久独立 policy；先由同一 LLC 的课程覆盖。出现可量化的负迁移，或动作机制明显不同，再分出专项教师。

没有专业滑雪采集数据，不妨碍在仿真中进行 RL。若使用人工参考、视频动作或仿真训练，展示中应准确说明。内部新模型可以参与开发、规划或运行时控制，但 HLC 默认指小型控制策略，不能自动等同于 LLM。

## 2. 开始训练前的物理前置条件

以配套物理文档为依据，锁定 G1、雪板、雪面与接触版本。至少完成：

- 单板沿板／横板阻力与旋转 90° 的方向一致性检查。
- 静载挠度、换刃、卸载与离地接触消失检查。
- 转弯机制与有限失抓验证；不能用高摩擦掩盖错误几何。
- 小跳落地、时间步收敛和机械能／外功检查。
- 关节限位、执行器限幅、雪板质量惯量与绑定方式确认。

禁止在训练中暗中施加根节点支撑、轨迹牵引或空中旋转力矩。课程允许显式初始化速度、姿态和角动量，但全流程验收必须由真实助滑和起跳产生这些状态。

物理版本改变后重跑相关基线。不要同时改物理、奖励和网络结构，否则无法定位收益或失败原因。

## 3. 控制架构与时间尺度

| 模块 | 职责 | 输出 |
| --- | --- | --- |
| HLC | 选线、调速、指定技能意图 | 短期运动命令；后续加入跳跃意图与目标 |
| 命令适配器 | 坐标变换、限速率、有效字段管理、技能切换约束 | 实际提交给 LLC 的命令 |
| LLC | 身体协调、雪板控制、接触适应与动作执行 | 主动关节位置目标 |
| PD／执行器 | 跟踪目标、执行限幅 | 关节力矩 |
| MuJoCo | 刚体、雪板弹性、接触与重力积分 | 下一物理状态 |

开发起点：物理 1000 Hz，LLC 100 Hz，HLC 10 Hz。分别对应 1 ms、10 ms、100 ms；PD 在物理子步运行。调整频率必须重新验证，不能将这些值当作稳定性保证。

HLC 每步命令由 LLC 连续执行 10 步；动作中途若触发真实终止立即结束，不强行运行剩余子步。局部地形变化、接触判断和姿态恢复不等待下一次 HLC 更新。

统一时间折扣：可按物理时间常数定义 `gamma(dt)=exp(-dt/tau)`。高层区间奖励为该区间内逐步折扣奖励之和，下一状态 bootstrap 使用对应实际持续时间的折扣。不要不加说明地在不同频率上使用相同 gamma。

## 4. 坐标与核心状态定义

### 4.1 方向必须分开

- 雪板朝向：板头方向。
- 运动方向：质心速度在参考雪面上的投影方向。
- 最大坡降方向：重力在当地雪面上的投影方向。
- 侧滑：运动与雪板方向的差；接触点横板速度提供局部信息。

跟踪运动方向不等于扭转雪板朝向。接近零速时运动方向不可靠，需要关闭对应奖励或使用有效掩码。

### 4.2 HLC 空间参考

采用以机器人为原点、Z 轴竖直、仅随水平参考朝向旋转的局部坐标系。旗门、地形和边界使用此系，身体倾斜不带动地图倾斜。

空中翻转时若身体朝向的水平投影退化，沿用连续参考方向或固定起跳参考系；不能产生随机坐标跳变。地图参考系与接触切向系分开：接触相关速度、刃角使用真实局部雪面。

### 4.3 命令的保持语义

HLC 在时刻 t 输出的相对运动方向，在该时刻转换成世界方向并保持到下一次更新；LLC 每步将其重新表达为当前局部方向。否则机器人转身后，“同一个相对命令”会继续跟着身体转动，改变原本目标。

地形法向改变时，根据约定将保存方向投影到参考切平面并处理退化。定义统一的参考法向（例如当前双板接触法向的载荷加权值；无接触时查询参考地面），并提供有效性标记。不要让 actor、reward 和评测使用不同方向定义。

## 5. HLC 动作与命令接口

### 5.1 基础滑行

```text
c_glide = [target_speed, sin(target_direction_error), cos(target_direction_error)]
```

方向是期望运动方向，不是板头方向；允许 LLC 利用适度侧滑调速。目标位置、旗门和赛道边界由 HLC 读取，转化为该运动命令。

策略内部可输出 `speed_raw` 和一个有界方向增量，再由适配器转换为三维命令。若直接输出 sin/cos，则需归一化并处理近零向量。

适配器要求：

- 速度限幅、方向变化率限幅及命令连续性。
- 初期只允许在 LLC 已验证命令范围内采样和执行。
- 限幅范围依据速度、坡度与试验结果保守设定，不宣称已知精确可达集。
- 记录 HLC 原始动作与实际提交命令；PPO 的 log probability 对应策略实际采样的原始动作，不能在 clipping 后重新伪造概率。
- 指令速度接近零时使用明确保持／停止语义；陡坡顺板方向未必能停住，不采样不可达的静止要求。

### 5.2 跳跃扩展

采用固定 schema 和字段掩码：

```text
command = {
  glide: {speed, direction},
  intent: {glide, straight_jump, spin},
  trick: {rotation_direction, target_turns, landing_heading},
  valid_mask: ...
}
```

意图由 HLC 或任务给出；`approach / takeoff / airborne / landing / recovery` 物理阶段由状态估计器维护，不能任意指令为“已落地”。不可逆的起跳动作需要承诺区间，不能每 100 ms 任意更换技能。先用显式规则和滞回避免抖动，再考虑学习切换。

目标圈数是意图，当前旋转进度是观测。圈数不能只用当前姿态恢复，因为完整一圈后姿态可能相同。

## 6. HLC Observation Space

第一版直接使用准确仿真状态和场地数据，不加入相机感知。以下为语义 schema；最终维度由实际关节模型、技能集合及地形编码确定，写入版本化注册表。

### 6.1 首版必需字段

| 分组 | 字段 | 处理与用途 |
| --- | --- | --- |
| 任务 | 目标速度区间、任务类型 | 定义任务意图，区分保持和滑行 |
| 运动 | 局部三维线速度、角速度、投影重力 | 惯性及身体姿态 |
| 姿态余量 | 身体离地高度、关键髋膝角、关节限位距离摘要 | 区分深蹲与伸直，判断缓冲空间 |
| 雪板 | 两板方向、相对位置、刃角、横板速度 | 判断方向、侧滑与板间关系 |
| 接触 | 两板接触标记、法向载荷均值和短窗口峰值 | 区分承载、卸载和冲击 |
| 坡面 | 局部法向、有效掩码 | 判断重力方向与坡度 |
| 路线 | 后续 3 个旗门的几何与有效掩码 | 提前选线；后续比较 1/3/5 门 |
| 边界 | 左右边界距离；复杂线路升级为边界几何 | 避免出界，保留转弯空间 |
| 控制历史 | 上一原始命令、实际命令、持续时间 | 理解限幅和动作惯性 |
| LLC 反馈 | 上一高层周期速度／方向误差、力矩限幅比例 | 识别下层执行不足 |

普通旗门可表示为：

```text
gate_i = [relative_center_xyz, width, sin(pass_direction), cos(pass_direction), valid]
```

提供当前待通过旗门的顺序状态；不规则旗门改用左右端点和通过平面。通关检测必须沿指定方向穿过有效开口，不能仅检查靠近中心点。

角度使用 sin/cos；方向无效、地形缺失和无接触必须有 mask，零填充本身不能区分缺失与真实零值。载荷可按系统重量归一化，关节位置按可用范围归一化。速度与距离尺度从实际任务范围确定并冻结到 checkpoint。

### 6.2 地形扩展

| 尺度 | 表示 | 作用 |
| --- | --- | --- |
| 近场 | 较密二维高度采样、坐标、有效掩码 | 猫跳、沟谷和局部接触变化 |
| 远场 | 稀疏高度／坡度、边界和跳台几何 | 提前调速、选线与起跳准备 |

不能只给沿当前轨迹的一维高度线，否则无法比较左右线路。预瞄距离随速度与动作空间增加，可用 `L >= v*T_response + d_maneuver` 做量级检查；制动距离使用试验得到的有效减速度，并考虑斜坡。

采样尺度若随速度变化，必须提供坐标或尺度。地形高程采用相对高度，不无意去除整体坡度信息；若减去局部平面，则另提供该平面坡度。

多帧地图先做坐标对齐，或单独逐帧编码；不直接拼接坐标不一致的网格。

### 6.3 跳跃观测

加入台唇相对位置与方向、出唇坡度、落地区范围和法向、滑出方向、技能意图、当前物理阶段、离地后时长、旋转进度、角速度及必要的角动量摘要。

预计飞行时间和落点误差只能由当前状态推算，不得使用仿真未来真值。空中阶段的地形信息必须覆盖落地区，不能只查询正下方。

### 6.4 历史与能力反馈

从 MLP 加最近 3–5 次低频状态／命令摘要起步；若存在显著不可观测的 LLC 内部记忆或长时依赖，再评估 GRU。循环状态在 episode 边界重置，不能只在 mini-batch 开头随意清零。

不要把 PPO critic 的 V 值解释为成功概率，也不要未经对齐直接比较不同专家 critic。后续能力预测器需以实际 `(state, command, outcome)` 训练和校准，第一版不依赖它。

## 7. LLC Observation 与 Action Space

LLC 读取：

- 主动关节位置与速度、局部线速度与角速度、投影重力。
- 当前统一命令、字段掩码、技能意图与物理阶段。
- 两板相对位姿、接触载荷及接触分布、沿板／横板速度。
- 雪板被动弹性状态或验证过的摘要；不能完全忽略显著弹性振动。
- 当前及前方局部地形、法向和有效性。
- 上一步动作和必要历史。

动作采用所有 G1 主动关节的位置目标：

```text
q_des = q_nominal + action_scale * action
tau = clip(Kp * (q_des - q) - Kd * qdot, actuator_limits)
```

雪板弹性关节无主动控制。教师、学生、HLC 训练期间保持关节顺序、动作缩放和 PD 一致。若更换 nominal pose 或 PD，必须更新接口版本，不仅更改 checkpoint 名称。

高斯 actor 可以作为 PPO 起点；评测明确使用均值动作还是采样动作。若动作有 tanh 等变换，概率实现需与所用 RL 库的分布约定一致。

## 8. 课程：从原 13 阶段到可实施训练

| 原阶段 | 调整后的任务 | 初始化与难度变量 | 验收重点 |
| --- | --- | --- | --- |
| S1 | 平地站立、缓坡横板保持 | 小姿态扰动、坡度 | 可达条件下保持，不靠隐形支撑 |
| S2 | 顺坡直滑 | 坡度、初速度、扰动 | 完成距离与滑出，不坐下或停滞 |
| S3 | 斜向滑行与侧滑辨识 | 小范围初始朝向与速度方向差 | 分开板朝向、运动方向、轨迹 |
| S4 | 左右运动方向跟踪 | 平滑目标方向、小到大转弯 | 实际轨迹改变且持续稳定 |
| S5 | 方向、速度与短程目标 | 先调速，再加入可达目标 | 不随机组合互相矛盾的终态 |
| S6 | 连续命令序列 | 连续转向、减速接转弯 | 多段完成，无明显技能遗忘 |
| S7 | 平整坡面连续旗门 | 先确定性引导器，后 HLC | 按序正确过门和滑出 |
| S8 | 横坡／坡度变化与调速 | 固定材质、逐项改变几何 | 提前调整速度与方向 |
| S9 | 单凸包／凹谷到连续起伏 | 幅度、曲率、间距 | 合理接触切换与冲击 |
| S10 | 规则到扰动猫跳 | 错列、高度、间距、路线 | 选线、吸收冲击与连续完成 |
| S11 | 低难度直跳与落地 | 临近落地状态、小跳台 | 着陆后稳定滑出 |
| S12 | 扩展跳台与落地包络 | 接触前法向速度、姿态、角速度 | 冲量、限幅、穿透、恢复 |
| S13 | 指定空中动作及全链路 | 参考片段、动作进度、起跳条件 | 正确动作＋真实起跳＋落地滑出 |

材质随机化单列，不与 S8 的几何变化混为一谈。先冻结材质验证几何课程，再加入有限摩擦和刚度变化；范围依据物理合理性及校准结果，不任意覆盖。

S11 的独立落地练习可在基础滑行稳定后提前开展，不需要等待猫跳全部成功。S13 可开发专项教师，不要求同一策略依次微调到最后。

### 8.1 命令可达性

先从可行轨迹或已成功 rollout 提取方向、速度与终点组合，再逐步扩大范围。短程目标需定义时间窗口和通过／停留语义；不要求任意一秒内到达任意位置。

方向命令使用限变化率随机过程、平滑样条或程序化转弯段；不逐步独立均匀采样。初始状态逐步扩展但避免大比例一开始就不可恢复。

### 8.2 旧任务保留与课程晋级

可从“60% 当前课程、30% 已学课程、10% 过渡／恢复任务”作为环境采样起点，按失败结构调整。比例属于任务重采样，不是把旧 PPO rollout 随意当当前 on-policy 数据。

晋级看独立评测，不看训练回报单独上涨。固定测试种子与额外随机种子分开。每次增加一类难度，保留旧任务回归；困难维度如速度、坡度、门距和起伏幅度分别记录。

## 9. 奖励与终止设计

### 9.1 LLC 基础奖励

```text
r = w_v * r_speed + w_d * r_direction + w_task * r_task
    - w_a * c_action_change - w_e * c_effort
    - w_l * c_joint_limits - w_c * c_bad_contact
    - w_f * c_failure
```

示例跟踪项：

```text
r_speed = exp(-((v_tangent - v_target)/sigma_v)^2)
r_direction = exp(-(wrap(chi - chi_target)/sigma_chi)^2)
```

`v_tangent` 定义为切向速度大小，方向另算；低速时屏蔽方向项。真实运动方向由速度计算，不能用躯干 yaw 替代。任务项要求滑出距离或完成事件，避免仅存活就得到高分。

每项先无量纲化，记录原值、加权值及累计贡献。权重通过消融和失败样本调整；不在没有数据时宣称某组固定权重最优。连续奖励按时间积分，过门、摔倒等事件奖励只计一次。

### 9.2 姿态约束

| 候选项 | 使用方式 | 避免的问题 |
| --- | --- | --- |
| 两板距离 | 合理区间外惩罚、交叉和碰撞约束 | 固定距离妨碍地形吸收 |
| 平行度 | 指定风格下弱约束，恢复时放宽 | 禁止犁式制动或必要恢复 |
| 身体反弓 | 有参考或明确转弯条件时再加入 | 固定角度与速度、半径不匹配 |
| 躯干竖直 | 不作为全程强奖励 | 阻止合理侧倾和空中动作 |
| 两板载荷对称 | 仅静态验证使用 | 阻止内外板分工 |
| 侧滑最小 | 仅刻滑子任务使用 | 禁止搓雪制动 |

动作平滑和能耗项不能大到阻止快速缓冲。空中／落地奖励按真实阶段管理，不凭策略自报阶段获得豁免。

### 9.3 HLC 奖励

主要使用合法路线进展、按序过门、速度区间、出界／漏门／摔倒。不要重复堆叠关节级风格奖励。

进展可用有界路线坐标的势能差做 shaping，避免绕圈或在同一门前反复刷分。距离下一门的简单下降不应成为唯一目标，否则鼓励直冲当前门而破坏下一门线路。

### 9.4 跳跃奖励与终止

- 起跳：有效通过台唇、满足入口速度和动作所需条件。
- 空中：动作目标／参考匹配，正确旋转方向与连续进度。
- 落地：姿态与坡面匹配、合理冲量，随后完成恢复与滑出。
- 不只奖励腾空或旋转圈数，否则可能学会无法落地的动作。

摔倒由任务阶段相关的身体碰撞、不可恢复状态或出界定义；空中翻转不能使用普通“躯干倾角超阈值”终止。时间上限截断与真实失败终止分开，按算法正确处理 bootstrap。

## 10. 算法与训练流程

### 10.1 基础配置

PPO 作为首个基线；LLC 与 HLC 使用独立 actor/critic、优化器和统计。可从 2–3 层、每层 256 单元的 MLP 起步，地形单独编码；容量不足再扩展。该结构不代表已验证最优。

并行环境数由实际仿真吞吐与内存测得，不能预设 GPU 能直接加速自定义接触管线。先测每秒物理步、LLC 步和回合数，再估算训练预算。

学习率、batch、rollout 长度、clip、entropy、GAE、归一化和随机种子必须配置化。首个实验沿用所选 PPO 实现的稳定基线，先解决环境与奖励，再做超参扫描。

### 10.2 分层训练顺序

1. 冻结物理，程序生成可达命令训练 S1–S6 的 LLC。
2. 冻结 LLC，确定性引导器过门，建立可控性基线。
3. 在实际 LLC 闭环上训练 HLC，使用相同命令适配器。
4. 收集 HLC 真实命令和失败入口，冻结 HLC 补训 LLC。
5. LLC 更新后重新评测并必要时重训 HLC；两层都有版本依赖。
6. 逐步加入地形与专项技能，最后训练完整线路。

两层不从随机初始化同时更新。PPO 更新仅使用对应行为策略生成的 rollout。若蒸馏导致策略更新，下一次 PPO 收集应重新进行，不能把过期 rollout 当作新策略数据。

### 10.3 高层环境伪代码

```text
reset:
  reset physics, LLC history, command adapter, task state
  return HLC observation

step(raw_high_action):
  command = adapter(raw_high_action, current_state)
  for each LLC step in high-level interval:
    obs_low = build_low_obs(command, current_state)
    target = LLC(obs_low)
    run physics substeps with PD(target)
    update contacts, task phase, gate events, tracking summaries
    accumulate time-consistent reward
    if terminated or truncated: break
  return high_obs, reward, terminated, truncated, diagnostics
```

## 11. 跳跃技能与衔接

从低难度临近落地状态训练恢复，再扩展到完整腾空，最后接真实助滑与起跳。落地初始化需匹配合理速度、姿态、角动量和地形，不随机制造大比例不可恢复状态。

难度主要按首次接触点的法向接近速度、姿态误差、角速度、剩余缓冲行程和坡面匹配程度组织；台高只是其中一项。应区分质心速度与含转动贡献的接触点速度。

空中动作可采用少量视频重建、人工关键帧或轨迹优化参考，先重定向并检查 G1 关节与动力学可行性。参考动作只提供监督，不能通过 kinematic override 控制最终评测。

过渡训练至少包括：转弯后释放载荷、助滑到起跳准备、起跳到收身、展开到首次接触、落地到下一次转弯。动作片段独立成功不等于衔接成功。

## 12. 专家分支与统一策略蒸馏

### 12.1 分支条件

先尝试统一基础 LLC。若加入猫跳后基础滑行在相同评测集明显退化，且通过任务采样与奖励调整仍无法消除，再分出猫跳教师。跳跃／空中动作可独立开发。教师按能力分组，不按 13 个课程编号分组。

所有教师共享物理、动作、控制周期和统一输入语义；允许额外教师观测，但学生缺失信息造成的可辨识性问题必须另行处理。第一版教师和学生都使用同样的仿真可得状态。

### 12.2 目标学生

```text
a = unified_LLC(observation, command, skill_intent, physical_phase, history)
```

单个网络可具有条件输入；无需取消技能意图。无条件策略无法在完全相同状态下同时决定直跳和转体。

### 12.3 MOPD 式连续控制方案

这里借鉴 Multi-Teacher On-Policy Distillation 的多教师、学生分布监督思想，不直接复用 LLM token-level 损失。

A. 教师轨迹行为克隆，先给学生一个能运行的初始化。  
B. 学生执行 rollout，在学生实际状态上查询适用教师。  
C. 学生学习教师动作或动作分布，反复收集新学生状态。  
D. 全线路 PPO 微调，并保留有适用性权重的蒸馏约束与旧任务评测。

```text
L_distill = E_on_student_states[
  teacher_valid_weight * weighted_MSE(student_action_mean, teacher_action_mean)
]
```

动作按统一量纲归一化；也可用方向明确的 KL，例如 `KL(teacher || student)`。连续动作高斯的均值、方差与动作变换必须一致，不能将探索方差随意当成技能质量。动作均值 MSE 是第一版简化，不等价于所有 OPD 目标。

教师路由依据任务意图、真实阶段和验证过的状态适用范围，第一版规则路由即可。不要把多个专家关节动作简单平均，也不要未经校准用不同教师 critic 的最大值选教师。

循环教师需要沿学生实际历史更新隐藏状态，不能每次查询都重新初始化。初期混合教师控制帮助采样时应标注为 mixed-policy warm-up，不能称纯学生 on-policy。

教师在严重失稳状态上也可能错误。对超出能力范围状态减少蒸馏权重、使用恢复专家或合理终止；不能盲目认为教师标签全部正确。

### 12.4 衔接覆盖

让下一技能使用上一技能真实生成的入口状态训练。缺少衔接行为时先补教师／过渡控制器，蒸馏不能凭空产生监督中不存在的能力。

蒸馏 batch 按任务与阶段分层采样，提高短暂起跳、首次接触和恢复的比例，避免长滑行片段主导损失。保留学生状态数据用于监督学习可以接受，但 PPO rollout 的 on-policy 要求另行遵守。

学生整合后冻结新 LLC，重新训练或验证 HLC；即使专家技能保留，响应时延变化也可能使旧 HLC 选线失效。

## 13. 评测与晋级标准

以下阈值是建议的开发门槛，正式实验前固定到配置。不能训练完再选择有利阈值。

| 层面 | 指标 | 建议验收方式 |
| --- | --- | --- |
| LLC 基础 | 指令段完成率、速度误差、方向误差、摔倒率 | 可达命令测试集成功率先达到 90%，另按速度／坡度分桶 |
| 旗门 HLC | 全线路成功、漏门、出界、完成时间 | 按序全过门＋规定滑出才算成功 |
| 猫跳 | 路线完成、冲击、接触切换、限幅 | 对高度、间距和速度分别报告 |
| 跳跃 | 动作完成、真实起跳、着陆及恢复 | 在固定恢复时间／距离内继续滑行，无异常物理 |
| 衔接 | A→B 成功率、入口状态覆盖 | 独立报告，不以单技能成功替代 |
| 蒸馏 | 每项教师／学生成功率及误差差值 | 可先要求成功率下降不超过 5 个百分点，结合置信区间 |
| 回归 | 旧任务成功率下降 | 超过预设容差即暂停扩课程 |

开发评估可从每任务桶约 100 回合起步；报告置信区间，罕见失效不能由 100 回合无事故证明。关键里程碑至少比较 3 个独立训练种子；算力不足时记录未完成的统计验证，不把单种子结果称为稳定结论。

区分 ID 与 OOD：未见随机种子、未见门距组合、未见坡度／速度范围分别报告。冻结训练／验证／测试场地划分，模型选择不用最终测试集。

首版必须做的消融：

- 1 个旗门与 3 个旗门预瞄。
- 有／无 LLC 跟踪及限幅反馈。
- 弱姿态约束与强固定姿态约束。
- 离线行为克隆与学生 rollout 蒸馏。
- 有／无过渡片段训练。

按实际阶段开展，未训练跳跃前不做无关蒸馏实验。

## 14. 实验记录与故障定位

每个 checkpoint 保存物理配置 hash、观测／动作 schema、PD、归一化、课程分布、奖励权重、控制频率、随机种子、代码版本及依赖的 LLC/HLC checkpoint。

每回合记录原始与实际命令、轨迹、速度、方向、侧滑、刃角、双板载荷、关节状态、执行器限幅、接触／技能阶段、过门事件、失败原因、各奖励分项及求解器异常。

| 现象 | 优先检查 |
| --- | --- |
| 原地不动或坐着滑 | 成功定义、存活奖励、低速目标是否可达 |
| 板已转但轨迹没转 | 用错方向奖励、接触坐标、刻滑机制、侧滑容量 |
| 当前门能过、下一门总失败 | 预瞄不足、速度过高、命令可达性 |
| 猫跳后忘记直滑 | 任务采样、奖励冲突、归一化变化 |
| 起跳会做但完整路线失败 | 前技能出口分布与后技能入口不匹配 |
| 蒸馏误差小但落地失败 | 关键阶段采样不足、动作累积误差、教师适用范围 |
| 换 LLC 后 HLC 退化 | 下层响应变化、命令语义或时延不一致 |
| 训练成功但减小步长失败 | 数值漏洞、接触与执行器实现 |

以下为建议文件结构，尚未创建实现文件：

```text
configs/physics/       冻结物理参数

```

| 里程碑 | 交付 | 决策门 |
| --- | --- | --- |
| M0 | 物理验收与统一接口 | 接触、动作、单位、坐标正确 |
| M1 | S1–S6 基础 LLC | 连续方向／速度命令可控 |

M3/M4 可按展示重点调整优先级。训练时间需根据实测吞吐、学习曲线和算力预算估计；本文不承诺固定天数或样本数。

## 17. 参考资料与证据边界

以下来源已在前述讨论中查阅。它们支持方法选择，不直接证明本项目的滑雪可行性，也不为本文数值初值背书。

- [Policy Distillation](https://arxiv.org/abs/1511.06295)：多任务策略整合的基础方法。
- [DAgger](https://arxiv.org/abs/1011.0686)：在学习者诱导的状态分布上查询专家，处理模仿分布偏移。
- [MOPD](https://arxiv.org/abs/2606.30406)：LLM 多教师 on-policy 蒸馏；本文仅迁移其训练组织思想。
- [Distillation-PPO](https://arxiv.org/abs/2503.08299)：人形运动中的蒸馏与 RL 结合路线。
- [DeepMimic](https://arxiv.org/abs/1804.02717)：动作参考与任务奖励结合，包含动态动作和重定向。
- [AMP](https://arxiv.org/abs/2104.02180)：从动作片段学习风格先验；没有足够参考时不作为首版必选项。
- [RobotKeyframing](https://arxiv.org/html/2407.11562v2)：带位置、姿态及时序高层目标的控制参考。
- [VP-Nav](https://arxiv.org/abs/2112.02094) 与 [TOP-Nav](https://arxiv.org/abs/2404.15256)：将本体反馈和运动能力纳入导航规划的依据。
- [Skill-Nav](https://arxiv.org/abs/2506.21853)：waypoint 分层接口的另一条路线；若方向／速度接口成为具体瓶颈，可在基线后比较，不预先混用两套命令。
